## 1. 项目背景与定位

NUS 计算机学院的 **「MSc DFT(数字金融科技硕士)申请人 AI 助手」**(FT5007 capstone)。整个产品是一个覆盖学生**全生命周期**(潜在申请人 → 申请人 → 录取 → 在读 → 毕业 → 校友)的 AI 助手,目标是**替代大部分人工客服**:用自然语言回答问题、自动化流程、给个性化建议、主动提醒,只有复杂情况才转人工。

整个系统采用 **「supervisor(总调度) + 专家 agent」** 架构。**我负责其中第 4–7 项功能**:

| # | 模块 | 一句话功能 | 用户提问示例 |
|---|------|-----------|------------|
| **4** | 申请清单 | 你该交哪些材料、还缺什么 | 「我的申请还缺什么?」 |
| **5** | 状态追踪 | 申请到哪一步了、该做什么、主动提醒(可真发邮件) | 「我的申请状态如何?」 |
| **6** | 项目对比 | 把本项目和其它学校客观对比 | 「这个项目和别的金融科技硕士比怎么样?」 |
| **7** | 选课与职业 | 按目标岗位推荐选课、分析技能差距 | 「想做金融科技产品经理该选什么课?」 |

## 2. 整体架构

```
                 ┌──────────────────────────┐
   用户输入  ───▶ │  对话/意图模块(队友负责)  │  把用户的话变成 {意图, 槽位, 用户画像}
                 └─────────────┬────────────┘
                               │  统一上游契约
                               ▼
        ┌─────────────────────────────────────────────────┐
        │   supervisor.route(意图, 画像, 槽位)              │ ← 总调度
        │   · 按生命周期分流(申请人流程 / 在读学生流程)     │
        │   · 官方资料置信门控(不确定就转人工)             │
        ├──────────┬───────────┬───────────┬──────────────┤
        │ #4 清单   │ #5 追踪    │ #6 对比    │ #7 选课/职业  │  ← 我负责的四个专家 agent
        │ agent+    │ agent+    │ agent+    │ agent+        │
        │ engine    │ engine    │ engine    │ engine        │
        └────┬──────┴─────┬─────┴─────┬─────┴──────┬────────┘
             │            │           │            │
   ┌─────────▼──┐  ┌──────▼─────┐ ┌───▼────────┐ ┌─▼──────────────┐
   │ 招生规则    │  │ 状态机+通知 │ │ 竞品数据集 │ │ 课程目录+技能映射 │  ← 数据资产(data/)
   │ (mock/规则)│  │ +SMTP 邮件  │ │ (带来源)   │ │ (真实 NUSMods)   │
   └────────────┘  └────────────┘ └────────────┘ └─────────────────┘

   旁路:  RAG/知识检索(common/retriever)   ·   Escalation 转人工(队友模块)
```

**每个 agent 都拆成两半**(这是全项目最重要的设计):
- **engine(规则引擎)**:用纯 Python **确定性**地算出结论(缺什么材料、状态、对比结果、推荐哪些课)。
- **agent(叙述层)**:只负责把结论**写成人话**;没配 AI 时自动降级为模板。
- **效果**:同样的输入永远得到同样的结论 → 可测试、可复现、可审计、**不会瞎编**。

## 4. 核心设计原则

| 原则 | 含义 | 效果(你会看到什么) |
|------|------|--------------------|
| 裁决归规则,叙述归 LLM | 结论由规则定,AI 只写人话(或在护栏内挑选) | 结果稳定、不瞎编、出问题能追溯 |
| 统一数据契约 | 所有 agent 只吃一种 `UserProfile`,输出一种信封 | 各模块/队友无缝对接,少返工 |
| 外部系统全 mock | 招生/CRM 用本地模拟,形状对齐真实 API | 现在能演示,将来能无痛接真系统 |
| 离线可跑 + 优雅降级 | 没配 AI key / 邮箱 / 网络也能用 | 永不因为缺配置而崩;配了就增强 |
| 合规优先 | 答案分级、来源引用、不排名、需 consent、低置信转人工 | 满足项目对「可信、可审计」的硬要求 |

## 5. 各模块功能详解

### #4 申请清单(`agents/checklist`)
- **逻辑**:按 `admissions_rules.json` 的规则,根据画像(国籍/学历/经验/学历认定)决定**该交哪些材料**;每项算出状态(缺失/已交/审核中/已核验/被退)、截止日期、紧急度。AI 给每项写一句「为什么需要」。
- **效果**:申请人看到一张个性化清单——哪些必交、哪些视情况、哪些还缺、哪些临近截止。
- **合规点**:国籍→语言证明是官方规则;学历信息不全时走「追问澄清」而非乱触发。

### #5 状态追踪 + 通知引擎(`agents/tracker`)
- **逻辑**:用 mock 状态机模拟招生系统(`DRAFT→SUBMITTED→UNDER_REVIEW→{OFFER/补件/候补/拒}`),把状态码**翻成人话** + 下一步 + 预计日期;与 #4 联动列出**还缺的材料**。
- **通知引擎(本月新增)**:
  - 申请人可**自配偏好**:渠道(应用内/邮件)、频率(立即/每日汇总/关闭)、按里程碑静音。
  - **真发邮件**:配好 SMTP 就把里程碑提醒**真发进邮箱**;一天多条可合并成一封;同一条**只发一次**(去重);没配邮箱就只记录不真发(离线降级)。
- **效果**:申请人能收到「该确认录取了/该补材料了」的真实邮件提醒,且不会被重复轰炸,也能自己设定怎么被打扰。

### #6 项目对比(`agents/comparator`)
- **逻辑**:从**人工审核、带来源**的竞品数据集(NUS / SMU / NTU / HKUST 等真实公开数据)取数,按维度对比;按你的目标岗位算「契合度」。
- **fact/synthesis 分离(本月深化)**:每个对比单元标三态——`verified`(官方核验事实,带来源)/ `unknown`(官方未公开)/ `synthesis`(AI 归纳的解读);**事实**与 **AI 综合分析**在结构上分开。
- **防排名护栏**:AI 写的对比叙述若出现「A 比 B 好/排名第一」等措辞,**自动拦截并回退**安全模板。
- **效果**:申请人看到一张带来源链接的客观对比表(每格标明是事实还是 AI 解读)+ 一段「按你目标更契合谁」的分析,且**绝不出现学校排名**。

### #7 选课与职业(`agents/navigator`)
- **逻辑(本月重写)**:
  1. **规则建候选池**:岗位推荐课 ∪ 能补你技能缺口的课,**排除你已修过的**,且都来自真实课程目录。
  2. **LLM 受约束挑选**:AI 在候选里挑选/排序并解释,但**只能从候选里选**;编造的课**一律丢弃**。
  3. **确定性兜底**:没配 AI key / 离线 / AI 乱答 → 走规则排序。`selection_source` 标明这次是 AI 挑的还是规则挑的。
- **已修进度感知**:已修过的课会(a)被排除出推荐、标✓已修;(b)通过「模块→技能」映射**缩小你的技能缺口**;(c)算进**准确的毕业进度**(不重复计)。
- **选课 vs 职业分流**:问「选什么课」给课表;问「职业路径」给岗位-技能-补缺口分析。
- **效果**:在读学生看到「你已修 X;接下来建议选 Y、Z(各补什么技能)」+ 准确学分进度;且**绝不推荐不存在的课**;关个性化时不把你的数据送出系统。

### 共享底座与配套(简表)

| 模块 | 作用 |
|------|------|
| `admin/`(录入工具) | 管理员用自然语言改数据,经 AI 编译→校验→diff→确认→归档+审计;运行时引擎只读确定 JSON |
| `refresh/`(刷新管线) | 从 NUSMods 抓真实课程;可信源自动放行,异常/不可信源入人工队列;竞品数据**永远强制人工审核** |
| `eval/`(评估) | 记分卡(12/12 回归门)+ RAG/技能匹配阈值校准 |
| `student/`(学生端 Web) | 自然语言或上传简历 → AI 提取信息 → 可编辑确认表单 → 一次出 #4+#6+#7 三块结果 |

## 6. 逻辑流程

### 6.1 学生端整体流程(用户视角)
```
打开学生网页
   │
   ├─ 用自然语言描述自己 / 上传简历(Word/PDF)
   │        │ (需 AI key)
   │        ▼
   │   AI 提取信息(受合法选项约束,非法值丢弃)
   │        ▼
   ├─ 回填到「可编辑确认表单」 ← 学生检查/改正(含手填已修模块)
   │        ▼
   └─ 一次性得到三块结果:
         #4 申请清单(缺什么)   #6 项目对比(带来源)   #7 选课与职业建议
```

### 6.2 #7 推荐内核流程(本月核心)
```
目标岗位 ─▶ ① 规则建候选池        ② LLM 在候选内挑选+排序+理由
            (岗位课 ∪ 按缺口纳入,        │
             排除已修,来自真实目录)       ▼
                                ③ 校验:不在候选(编造)→ 丢弃
                                          │
                                          ▼
                                ④ 兜底:无 key/离线/全无效 → 规则排序
                                          │
                                          ▼
                                 输出待修推荐 + 已修✓ + 毕业进度 + selection_source
```
> **三道保险**:候选池(只放真课、排除已修)→ 校验(丢弃编造)→ 兜底(永远有确定结果)。**结果永不包含不存在的课。**

### 6.3 #5 通知投递流程
```
配置偏好(渠道/频率/静音)
        │
        ▼
due_now(预览)  ── 算出「现在该发什么」,去掉已发过的、按频率分组(立即/每日汇总)
        │            ⚠ 只读,不真发
        ▼
dispatch_due(投递)
        ├─ 邮件渠道 + 有邮箱 + 配了 SMTP → 真发邮件(163/QQ 用 SSL 465)
        ├─ 否则 → 只记录(record-only,离线)
        └─ 写「已发记录」→ 同一条永不重发
```

### 6.4 数据契约(与队友对接)
```
对话/意图模块 ──{intent, profile, slots}──▶ supervisor.route ──▶ 我的 agent
                                                              │
   ┌──────────────────────────────────────────────────────────┤
   ▼                                                           ▼
统一返回信封 AgentResponse                              低置信/例外 → Escalation(转人工)
{status, answer_type, speakable, data, sources, escalation}
```

## 8. 使用说明

### 8.1 安装
```bash
pip install -r requirements.txt
```

### 8.2 命令行演示(用内置虚拟用户,无需任何配置)
```bash
python run.py --list-profiles          # 查看内置演示用户
python run.py checklist --profile 1    # #4 申请清单
python run.py status    --profile 3    # #5 申请状态
python run.py compare   --profile 1    # #6 项目对比
python run.py courses   --profile 6    # #7 选课(在读学生 demo,演示已修排除)
python run.py career    --profile 6    # #7 职业路径
python run.py notify    --profile 5    # #5 通知:预览→投递→去重
python run.py smtp-test                # #5 发一封测试邮件验证 SMTP(需先配置)
```

### 8.3 网页端
```bash
python -m student.webapp     # 学生端  http://127.0.0.1:5001
python -m admin.webapp       # 管理员端 http://127.0.0.1:5000
```
- 学生端:用自然语言/简历 → 确认表单 → 出 #4+#6+#7 结果。
- 管理员端:选数据 → 输自然语言 → 看 diff → 确认写入(带历史/回滚)。

### 8.4 配置 AI(可选,启用真实叙述与简历提取)
在任一 Web 应用的 `/settings` 页填入 DeepSeek key,或设环境变量 `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL`。**不配也能跑**(自动走模板)。

### 8.5 配置 SMTP 真发邮件(可选,见 README 专节)
```bash
set SMTP_HOST=smtp.163.com
set SMTP_PORT=465
set SMTP_USERNAME=你的邮箱
set SMTP_PASSWORD=授权码        # 不是登录密码
python run.py smtp-test          # 打印 SENT: True 即成功
```
> 端口 465 用 SSL(163/QQ);587 用 STARTTLS(Gmail)。个人 outlook.com 已被微软禁用 SMTP,请用 163/QQ/Gmail。

### 8.6 测试与评估
```bash
python -m pytest tests/ -q     # 267 passed + 1 skipped(全离线)
python -m eval.runner          # 记分卡 12/12
```

## 11. 合规与安全

| 要求 | 实现 |
|------|------|
| 不编造 | 推荐/对比只来自人工审核数据;#7 校验每个 AI 选择;#6 防排名护栏 |
| 事实与推断分开 | #6 每格标 verified/unknown/synthesis;答案分级 official/advisory/recommendation |
| 需 consent + 公平 | 关个性化→不出个性化推断(含不发给 AI);技能推断排除国籍 |
| 安全降级 | AI/embedding/邮件 任一失败 → 落到确定性离线路径,不崩 |
| 凭据不泄露 | 只存环境变量或 gitignore 本地文件;已核验未入库 |
